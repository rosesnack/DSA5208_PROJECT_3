# Parallel PageRank on Vanda

[Report](report.pdf) · [Editable report](report.md) · [GitHub repository](https://github.com/rosesnack/DSA5208_PROJECT_3)

C++17 implementations of synchronous, uniform-preference PageRank: Serial, OpenMP, MPI, MPI+OpenMP, CUDA, Kokkos OpenMP/CUDA, MPI+CUDA, and MPI+Kokkos. Every MPI implementation supports complete-vector **Allgatherv** and exact selective **Halo** exchange.

The published results contain **45 fixed graphs and 19,530 configurations**, **372 growing-input configurations/controls**, **59 matched collective-policy/context/binding configurations**, and **five additional 512-core measurements**. Each configuration uses one warm-up and five timed solves; reported times are their median. Cross-graph speedup summaries explicitly use geometric means of matched ratios. The report combines full runtime tables with Serial-relative heatmap colors: cell numbers are seconds; bold, outlined cells mark the fastest observed method within each graph and node class.

The source archives preserve original measurement bytes, validation records and job identities. A location such as `results/raw/fixed_cpu.zip::fixed/.../summary.json` identifies a ZIP member; the analysis reads it directly without unpacking. The Google score vector is included separately as `results/raw/google_ranks.csv.gz` so the real-data conclusions can be recomputed. Full vectors for other large runs can be regenerated by running the solvers and independent validators.

## Rebuild the published tables and report

No cluster connection or new performance run is needed:

```bash
git clone --depth 1 https://github.com/rosesnack/DSA5208_PROJECT_3.git
cd DSA5208_PROJECT_3
python3 -m pip install -r requirements-report.txt
python3 scripts/analyze_results.py
python3 scripts/analyze_controls.py
python3 scripts/build_report.py
```

Python 3.9+ is required. Analysis verifies archive SHA-256 values, the five original timings, numerical criteria and saved validation evidence. `results/tables/audit.json` records the counts and source-manifest hashes. The display tables retain their exact source locations and comparison baselines.

Report figures are vectors. To refresh PNG previews as well, install Poppler and pass `--pdftoppm /path/to/pdftoppm` to `build_report.py`. Display equations are compiled by pdfLaTeX with `amsmath`/`amssymb`; unchanged checked-in equation PDFs can be reused without a TeX installation. The main report keeps four sections, followed by references and the AI-usage statement.

## Build the algorithms

Required: CMake 3.16+, a C++17 compiler with OpenMP, and MPI development libraries. The Vanda measurements used Release builds, GCC 13.3.0, Open MPI 4.1.8, Platinum 8452Y CPU nodes and A40 GPU nodes. CUDA measurements used toolkit 12.4.1; Kokkos is pinned to 4.5.01.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

The base targets are `pagerank_serial`, `pagerank_openmp`, `pagerank_mpi`, and `pagerank_hybrid`.

For native CUDA, configure a separate directory with `-DBUILD_CUDA=ON -DBUILD_MPI_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=86`. For Kokkos, first install the pinned dependency with its OpenMP or CUDA backend, then configure with `-DBUILD_KOKKOS=ON -DBUILD_MPI_KOKKOS=ON -DCMAKE_PREFIX_PATH=<kokkos-install>`; keep CPU and CUDA builds separate. The complete Vanda build recipes are `scripts/vanda_cpu_build_job.pbs` and `scripts/vanda_gpu_build_job.pbs`.

```bash
git clone --depth 1 --branch 4.5.01 https://github.com/kokkos/kokkos.git third_party/kokkos
# On Vanda: build within a compute-node allocation, using the supplied build jobs.
qsub scripts/vanda_cpu_build_job.pbs
qsub scripts/vanda_gpu_build_job.pbs
```

For an OpenMP Kokkos build outside the supplied Vanda recipes:

```bash
cmake -S third_party/kokkos -B build-kokkos-lib -DCMAKE_BUILD_TYPE=Release \
  -DKokkos_ENABLE_OPENMP=ON -DCMAKE_INSTALL_PREFIX="$PWD/kokkos-install-openmp"
cmake --build build-kokkos-lib --parallel
cmake --install build-kokkos-lib
cmake -S . -B build-kokkos -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_KOKKOS=ON -DBUILD_MPI_KOKKOS=ON \
  -DCMAKE_PREFIX_PATH="$PWD/kokkos-install-openmp"
cmake --build build-kokkos --parallel
```

## Prepare inputs

```bash
python3 scripts/prepare_data.py
python3 scripts/generate_scaling_graphs.py --output-root data/experiments
```

The first command downloads SNAP web-Google and recreates the two original synthetic inputs. The second generates the reproducible Uniform/Hub/Controlled families with seed 5208: three canonical inputs, the 36 size-density grid inputs, the three large inputs, and 27 growing-input graph identifiers. It writes graph manifests under `data/experiments/manifests/`. The large inputs have 12.8 million vertices and 204.8 million edges each; use `--fixed-only` to omit large/growing inputs for a smaller setup.

A custom manifest has one line per graph:

```text
name /absolute/path/to/edges /absolute/path/to/nodes
```

Use `-` for the node file when all vertex IDs appear in the edge file. `PAGERANK_DATASET_MANIFEST` selects this manifest; otherwise the programs use the original Google, Uniform and Hub paths.

## Execute and validate

```bash
export PAGERANK_DATASET_MANIFEST="$PWD/data/experiments/manifests/fixed_graphs.tsv"
export PAGERANK_RESULTS_ROOT="$PWD/results/runs/example"
export PAGERANK_ENVIRONMENT=local-release
export PAGERANK_WARMUPS=1 PAGERANK_REPEATS=5

./build/pagerank_serial
PAGERANK_OPENMP_THREADS='1 2 4 8' ./build/pagerank_openmp
mpiexec -n 4 ./build/pagerank_mpi --communication=allgather
mpiexec -n 4 ./build/pagerank_mpi --communication=halo
PAGERANK_HYBRID_THREADS=4 PAGERANK_HYBRID_MAX_TOTAL_THREADS=16 \
  mpiexec -n 4 ./build/pagerank_hybrid --communication=allgather
PAGERANK_HYBRID_THREADS=4 PAGERANK_HYBRID_MAX_TOTAL_THREADS=16 \
  mpiexec -n 4 ./build/pagerank_hybrid --communication=halo
```

Allocate at least `processes × threads` CPU cores and bind processes/threads to distinct cores. CPU resource curves use `C=pT`, with pure MPI `p=C,T=1` and hybrid `p=C/4,T=4`. Beyond 32 cores the principal line uses `n=C/32` nodes. Device methods use one process and one GPU per node; the published GPU comparisons use one/two nodes. Fixed-core comparisons vary p/T while retaining the same C.

Each output configuration contains `summary.json`, `timings.csv`, `history.csv`, and `ranks.csv`. Solve timing includes iterative computation, communication and device staging; graph loading, distribution and one-time setup are excluded. New runs go under ignored `results/runs/` and do not change the published measurement manifests.

Device executables follow the same dataset/result environment. On GPU nodes, for example:

```bash
./build-vanda-matrix-cuda/pagerank_serial
./build-vanda-matrix-cuda/pagerank_cuda
./build-vanda-matrix-kokkos-cuda/pagerank_kokkos
mpiexec --map-by ppr:1:node --bind-to core -n 2 \
  ./build-vanda-matrix-cuda/pagerank_mpi_cuda --communication=allgather
mpiexec --map-by ppr:1:node --bind-to core -n 2 \
  ./build-vanda-matrix-cuda/pagerank_mpi_cuda --communication=halo
mpiexec --map-by ppr:1:node --bind-to core -n 2 \
  ./build-vanda-matrix-kokkos-cuda/pagerank_mpi_kokkos --communication=allgather
mpiexec --map-by ppr:1:node --bind-to core -n 2 \
  ./build-vanda-matrix-kokkos-cuda/pagerank_mpi_kokkos --communication=halo
```

Independent checks rebuild the PageRank update from the raw edge list and compare parallel scores with Serial:

```bash
python3 scripts/validate_serial.py
PAGERANK_OPENMP_THREADS='1 2 4 8' python3 scripts/validate_openmp.py
python3 scripts/validate_mpi.py allgather --processes 4
python3 scripts/validate_mpi.py halo --processes 4
PAGERANK_HYBRID_THREADS=4 PAGERANK_HYBRID_MAX_TOTAL_THREADS=16 \
  python3 scripts/validate_hybrid.py allgather --processes 4
PAGERANK_HYBRID_THREADS=4 PAGERANK_HYBRID_MAX_TOTAL_THREADS=16 \
  python3 scripts/validate_hybrid.py halo --processes 4
```

GPU validation uses `validate_gpu.py cuda`, `validate_gpu.py kokkos Cuda`, and `validate_mpi_device.py` for distributed device runs. Kokkos OpenMP uses backend name `OpenMP`. Validation checks score IDs/degrees, finite nonnegative scores, mass error at most `1e-10`, L1 residual at most `1e-8` (plus rounding tolerance), and full-vector L1 difference from Serial at most `1e-8`.

### Vanda jobs

Use the paid performance queue for timings and the free queue for building, data processing and validation. PBS templates are kept separate:

- `vanda_cpu_job.pbs` and `vanda_gpu_job.pbs`: paid measurement jobs; `RUN_SCRIPT` selects a measurement script.
- `vanda_validate_job.pbs`: free job; `RUN_SCRIPT` selects a script of validator commands.
- `vanda_core_group_job.pbs` / `vanda_finalize_core_group_job.pbs`: existing grouped CPU measurement and independent validation.
- `run_vanda_mpi_scaling_suite.sh`, `run_vanda_kokkos_cpu_grid.sh`, and `run_vanda_cpu_core_weak.sh`: complete CPU layout/growing-input sweeps within the allocated layout.

For example, after exporting the dataset/result settings:

```bash
qsub -P <project-name> -v RUN_SCRIPT=scripts/run_cpu_suite.sh scripts/vanda_cpu_job.pbs
# Put the validator commands above into results/runs/validate_example.sh, then:
qsub -W depend=afterok:<performance-job-id> \
  -v RUN_SCRIPT=results/runs/validate_example.sh scripts/vanda_validate_job.pbs
```

Set the PBS `select`, `mpiprocs`, `ompthreads`, and walltime for the chosen layout; the report tables define the measured configurations. Cluster node availability and project credits determine when a job starts.

### Collective-policy controls

The main experiments retain Open MPI automatic selection. The installed fixed selector uses `coll_tuned_use_dynamic_rules=0`. Diagnostic runs enable forced dispatch and change only the relevant collective: Alltoallv `1=basic_linear, 2=pairwise`; Allgatherv `2=Bruck, 3=Ring`. This switch is independent of OpenMP dynamic row scheduling.

Generate a same-allocation plan, then submit measurement and free validation separately:

```bash
python3 scripts/make_control_plan.py --graph strong_uniform \
  --manifest data/experiments/manifests/fixed_graphs.tsv \
  --processes 128 --nodes 4 --threads 1 --communication halo \
  --policies default a2av_linear a2av_pairwise \
  --reference-root <validated-serial-results-root> \
  --results results/runs/controls/p128 --output results/runs/control_p128.json
qsub -P <project-name> -l select=4:ncpus=32:mpiprocs=32:ompthreads=1:mem=32gb \
  -v CONTROL_PLAN="$PWD/results/runs/control_p128.json" scripts/vanda_collective_control_job.pbs
qsub -W depend=afterok:<performance-job-id> \
  -v CONTROL_PLAN="$PWD/results/runs/control_p128.json" scripts/vanda_collective_control_validation.pbs
```

For the Allgatherv transition, select `--implementation hybrid --threads 4 --communication allgather`, p=8/16/32 on n=1/2/4, and policies `default agv_bruck agv_ring`. The certificate checker can be exercised independently with `python3 scripts/check_collective_certificate.py`.
